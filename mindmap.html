Style JSON — bản đồ tư duy cho một spec rối

Toàn bộ style spec (v8 + phần mở rộng Mapbox v3) thực ra chỉ trả lời bốn câu hỏi. Trang này vẽ lại spec theo bốn câu hỏi đó, bằng số liệu đo từ chính mapbox-standard.json đang dùng (150 layers, 80 paint props, 136 expression ops).

Bản đồ tổng — style.json có gì?

Cách nhớ: style.json = công thức nấu ăn. Sources là nguyên liệu, layers là các bước theo thứ tự, paint/layout là cách nêm từng bước, lights/terrain là cái bếp. Mọi field còn lại chỉ là chú thích quanh bốn thứ này.

Một layer đọc thế nào trong 10 giây?

Mỗi layer trả lời đúng một chuỗi: lấy dữ liệu nào → lọc gì → vẽ kiểu gì → tô ra sao. Ví dụ thật — layer tường chu vi indoor:

{
  "id": "indoor-building-walls",           ← tên duy nhất, để setPaintProperty/moveLayer
  "type": "fill-extrusion",               ← VẼ KIỂU GÌ (khối 3D)
  "source": "indoor",
  "source-layer": "indoor_floor",          ← LẤY DỮ LIỆU NÀO (tileset + lớp trong tile)
  "minzoom": 16,                            ← chỉ tồn tại từ z16
  "filter": ["is-active-floor", ["get","id"]],  ← LỌC feature (expression)
  "layout": { "visibility": "visible" },    ← hình học/sắp đặt — quyết định lúc BUILD TILE
  "paint": {                                ← màu mè — đổi được TỪNG FRAME, không rebuild
    "fill-extrusion-height": 3.05,
    "fill-extrusion-color": "hsl(220, 25%, 100%)"
  }
}

Vì sao có cả layout lẫn paint?

Ranh giới là chi phí: đổi layout (vd line-cap, text-field) phải build lại geometry của tile trong worker; đổi paint (màu, opacity, height) chỉ cập nhật uniform/buffer — tức thì. Đây là điểm gây rối số 1 của spec, và là lý do runtime API tách setLayoutProperty/setPaintProperty.

Thứ tự mảng layers = thứ tự vẽ

Phần tử sau đè lên phần tử trước (painter's algorithm), riêng khối 3D dùng depth test. Muốn label nằm trên đường → layer symbol đặt sau layer line. Không có z-index — vị trí trong mảng chính là z-index.

Chi tiết — 9 loại layer, loại nào vẽ gì?

Mỗi type là một pipeline render riêng (bucket + shader riêng). Xếp theo mức độ xuất hiện trong Standard:

Quy tắc chọn type khi tự viết layer: dữ liệu là đường → line, vùng phẳng → fill, vùng có chiều cao → fill-extrusion, chữ/icon → symbol, vật thể thật 3D → model. Một feature có thể được vẽ bởi nhiều layer cùng lúc (sàn indoor = fill floor + extrusion walls + symbol label — 3 layer, 1 nguồn).

Expression — vì sao JSON đầy ngoặc vuông lồng nhau?

Expression là ngôn ngữ hàm viết bằng mảng JSON, đọc như Lisp: phần tử đầu là tên hàm, phần còn lại là tham số. Chỉ cần thuộc 6 hàm là đọc được ~90% style thật:

HàmĐọc làSố lần trong Standard
["get","type"]lấy thuộc tính type của feature722
["match", x, a, ra, rb]switch/case: x==a → ra, else rb582
["interpolate", ["linear"], ["zoom"], 16,0, 18,3]nội suy theo zoom: z16→0, z18→3314 (zoom: 303)
["case", đk, a, b]if/else270
["config","lightPreset"]đọc biến người dùng chỉnh (schema) — fork: lightPreset đổi được lúc runtime (từ 13.3.1-mapzone.5), config khác cố định lúc load877
["step", ["zoom"], a, 16, b]bậc thang: dưới z16 → a, từ z16 → b166
Mẹo đọc nhanh: gặp mảng lồng sâu, đọc từ ngoài vào và chỉ hỏi "hàm gì? input camera (zoom) hay input feature (get)?" — camera-input thì cả layer đổi theo zoom; feature-input thì từng đối tượng một khác nhau (data-driven, tốn thêm buffer GPU).

Style đi qua pipeline nào trước khi thành pixel?

Đây là điều làm spec bớt rối với team mình: bạn không cần nhớ spec Mapbox v3 đầy đủ — chỉ cần nhớ hợp đồng maplibre:* (xem trang Reference, mục ★ MapZone extensions) và mục ★ Building 3D. Các nhóm chính:

NhómVí dụTrạng thái

Cái gì cố ý KHÔNG hỗ trợ? (để khỏi đi tìm)

bỏ Layer clip & building

Đục lỗ 3D building trên floorplan và building thủ tục. Fork thay bằng substitute app-level (IndoorManager ẩn layer) — đủ cho nhu cầu hiện tại.

bỏ fog, color-theme, featuresets, iconsets

Sương mù, LUT màu 22KB, Interactions API, icon raster-array. Không ảnh hưởng camera phố/indoor; icon đã có coverage-baking riêng.

bỏ flood-light (đèn hắt ban đêm)

Đèn hắt lên tường/mặt đất của building ban đêm. AO và vertical-scale ĐÃ hỗ trợ (xem ★ Building 3D); bo cạnh edge-radius đang phát triển.

bẫy Prop chuyển vào metadata → setPaintProperty có thể THROW

Prop ngoài spec v8 nằm trong metadata (maplibre:*). Web nhận setPaintProperty theo tên Mapbox cho các key line/symbol; key khác → sửa layer.metadata + triggerRepaint(). Prop Building 3D là prop thật — gọi setPaintProperty bình thường.
